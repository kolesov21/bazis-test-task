# Базис

Небольшое SPA для заметок со списками задач. Две страницы, интерфейс в стиле Notion, ручная история изменений и локальное хранение данных.

## Запуск

Требуется Node.js 24.11+ (рекомендуется ветка 24 LTS) и npm.

```sh
npm ci
npm run dev
```

Откройте http://localhost:3000. При первом запуске список пуст: создайте свою первую заметку. Демонстрационные данные не добавляются в хранилище.

Production-сборка:

```sh
npm run build
npm run preview
```

## Docker

```sh
docker-compose up
```

Для Docker Compose v2 эквивалентная команда — `docker compose up --build`. Приложение доступно на http://localhost:3000. Dockerfile использует два этапа: сборка на Node.js 24 и запуск только `.output` от непривилегированного пользователя `node`.

База данных и том Docker не нужны: заметки хранятся в браузере посетителя, а не в контейнере. Данные привязаны к origin: `localhost` и `127.0.0.1`, разные порты и браузеры имеют отдельные хранилища. Для внешнего размещения нужен HTTPS; localhost подходит для разработки.

## Проверки

```sh
npm run check         # строгие типы приложения и тестов, unit-тесты, production-сборка
npm run format:check  # единое форматирование
```

Браузерные тесты запускают production-сервер на отдельном порту 3001. Перед ними нужна свежая сборка.

```sh
npx playwright install chromium firefox webkit
npm run build
npm run test:e2e
```

Выбор браузера:

```sh
npm run test:e2e -- --project=chromium
npm run test:e2e -- --project=webkit --project=mobile
```

Мобильный проект — эмуляция iPhone 13 в WebKit, а не физическое устройство. Результаты и traces ошибок появляются в `test-results/`, не включённом в Git.

## Стек и структура

Nuxt 4.6.3 (`ssr: false`), Vue 3 Composition API, Pinia 4, TypeScript 6 strict, SCSS, Vitest 5 и Playwright. Версии закреплены в `package.json` и `package-lock.json`. TypeScript 6 выбран из-за несовместимости текущего `vue-tsc` с TypeScript 7.

```text
app/
  pages/index.vue          — список всех заметок, превью первых трёх задач
  pages/notes/[id].vue     — создание (/notes/new) и редактирование
  components/             — модальное окно, строка задачи, превью, иконки
  composables/            — сессия редактора и подтверждения
  domain/history.ts       — обратимые операции undo/redo
  domain/notes.ts         — модель, копирование, проверка данных
  domain/storage.ts       — версия схемы, чтение/запись, проверка ревизий, блокировка
  stores/notes.ts         — Pinia: сохранённые заметки и ошибки хранения
  plugins/storage.client.ts — загрузка данных и события других вкладок
  assets/styles/main.scss — точка подключения SCSS-модулей
  assets/styles/          — палитра, базовые стили, общие элементы и переходы страниц
tests/
  unit/                   — история, стор, форматы хранения
  e2e/                    — пользовательские сценарии в браузерах
```

UI-библиотек, библиотек истории, плагинов persistence, внешних шрифтов и аналитики нет. Интерфейс написан самостоятельно; модальное окно использует платформенный `<dialog>` с собственными стилями, управлением фокусом и обработкой клавиатуры.

Vue-файлы используют порядок `template` → `script` → `style scoped`. Стили компонентов и страниц, включая их адаптивные правила и анимации, находятся в собственных блоках `<style scoped lang="scss">`. Общие стили подключаются через `@use` в `main.scss`: базовые правила, кнопки, оформление документа, уведомления и переходы страниц. Общая палитра объявлена в `_tokens.scss`.

## Принятые решения

### Редактирование

Редактор работает с отдельной копией заметки. Пустое название и пустые строки задач блокируют сохранение: показывается пояснение, фокус переводится к первому ошибочному полю. Заметка без задач допустима. При сохранении пробелы по краям текстов удаляются.

Название и текст задач переносятся по ширине экрана, поля автоматически растут и уменьшаются по содержимому. Enter добавляет перенос строки; переносы сохраняются в заметке и черновике и отображаются в превью.

Главная показывает первые три задачи без интерактивных чекбоксов. Отмена редактирования и удаление всегда требуют подтверждения. Несохранённые изменения также защищены при переходе через ссылки приложения, включая переход непосредственно к другой заметке. Несуществующий идентификатор показывает понятное пустое состояние со ссылкой на список.

### История

Хранятся операции, а не полные снимки заметки:

- изменение текста: идентификатор поля, старое и новое значение;
- переключение чекбокса: идентификатор задачи и два булевых значения;
- добавление/удаление: одна задача и её позиция.

Непрерывный ввод объединяется до `blur`, паузы в 600 мс или следующего атомарного действия. Undo сначала фиксирует незавершённый ввод. Максимум — 50 записей, новое изменение очищает redo. Успешное сохранение, подтверждённая отмена и завершение сессии очищают историю. Восстановленный черновик начинает новую историю.

`Ctrl+Z` / `Ctrl+Shift+Z` и `⌘Z` / `⌘Shift+Z` управляют одной историей на всей странице, включая текстовые поля. Нативная отмена для этих событий подавляется, чтобы одно нажатие не вызывало два изменения. Для меню браузера обрабатываются `beforeinput: historyUndo/historyRedo`. `Ctrl+S` / `⌘S` сохраняют заметку. В открытом модальном окне сочетания редактора не действуют.

### Сохранённые заметки и вкладки

`localStorage` содержит отдельную запись `bazis:note:<id>` для каждой заметки:

```json
{
  "version": 1,
  "revision": "uuid",
  "note": {
    "id": "uuid",
    "title": "Название",
    "todos": [],
    "updatedAt": "2026-11-02T10:00:00.000Z"
  }
}
```

Запись выполняется только при сохранении или подтверждённом удалении. Удаление оставляет отдельный постоянный маркер `bazis:deleted:<id>` с `note: null` и новой ревизией и убирает исходное содержимое. Маркер всегда имеет приоритет: даже временно устаревший кеш браузера и поздняя запись в ключ содержимого не восстановят удалённую заметку. Событие `storage` обновляет список других вкладок; перед записью данные перечитываются и ревизия сверяется с базовой версией редактора.

Web Locks сериализуют проверку и запись одной заметки между вкладками. Во время ожидания сохранения редактор блокируется, но черновик по-прежнему сохраняется при перезагрузке. Если заметка удалена или изменена в другой вкладке, текст остаётся в редакторе, обычное сохранение блокируется и доступно «Сохранить как новую».

Без Web Locks остаётся оптимистическая проверка ревизии; абсолютная одновременность записей в таком окружении не гарантируется. Поддерживаемая цель — современные браузеры на HTTPS/localhost.

Неизвестная версия схемы, повреждённый JSON, запрет доступа и переполнение хранилища не затирают существующие данные. Пользователь получает сообщение; при неуспешном сохранении редактор и история остаются доступны. Нераспознаваемый черновик сохраняется без изменения и блокирует восстановление/редактирование до устранения проблемы с хранилищем.

### Черновики

`sessionStorage` содержит `bazis:draft:<route-id>` с версией схемы, рабочей заметкой, исходной ревизией и временем записи. Черновики изолированы между вкладками. Они записываются с debounce 400 мс, а также синхронно на `pagehide` и при скрытии страницы.

После перезагрузки предлагается восстановить или удалить черновик. Escape закрывает окно, сохраняет черновик и оставляет возможность вернуться к выбору. Сохранение/подтверждённая отмена убирают черновик. Закрытие вкладки завершает её сессию; перенос черновиков на другие устройства не предусмотрен.
